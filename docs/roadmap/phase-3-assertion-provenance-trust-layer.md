# Phase 3 Assertion Provenance Trust Layer

## Execution Control

Roadmap execution order is controlled by `docs/roadmap/READINESS_GATES.md`.
A phase advances only when the applicable readiness gate passes.

## Goal

Introduce the first governed assertion, provenance, and graph-partition layer
for doctrinal comparison without disturbing the current repository shell.

## Added In This Phase

- assertion governance and provenance policy docs
- named graph boundary guidance
- quarantine policy for AI-ingested material
- first-class substrate enums for assertion kind and graph partition
- first-class substrate types for assertion objects and provenance activities
- data templates for assertions, evidence, and comparison objects
- graph catalog and partition directories
- lightweight phase 3 validation scripts and workflows

## What This Phase Preserves

- the current canonical address shell
- existing authority zone and trust posture direction
- explicit asserted versus inferred separation
- structural separation for boundary and quarantine material

## Phase 4 Should Implement Next

- canonical examples using these new assertion and provenance types
- promotion paths between graph partitions
- registry integration for graph catalogs and assertion object families
- stronger provenance validation against evidence and source objects
- retrieval defaults that respect named graph trust boundaries

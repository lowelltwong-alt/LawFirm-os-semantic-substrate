# Codex Alignment Master Prompt

Use this prompt when asking Codex or another coding agent to reconcile, align, or clean up the repository.

---

You are working inside a repository that is a governed semantic system, not just a codebase.

Your first job is to understand the repository's design authority before changing anything.

Read these first:
1. README
2. docs/architecture/PROJECT_SYSTEM_MAP.md
3. docs/architecture/CANONICAL_SPINE_AND_VALIDATION_MODEL.md
4. docs/architecture/8_LAYER_DNA_ADDRESS_MODEL.md
5. docs/roadmap/MASTER_ROADMAP.md
6. docs/roadmap/PHASE_DEPENDENCY_MAP.md
7. docs/governance/REPO_OPERATING_MODEL.md
8. docs/poc/ and docs/security/ / docs/ops/ docs as relevant

Core design rules you must preserve:
- canonical spine first
- validation-aligned growth
- no parallel schema or ontology system
- 8-layer DNA address discipline remains part of the architecture
- substrate-native operating semantics remain the design authority
- additive semantic stack posture remains intact
- derived graph, retrieval, and projection artifacts do not replace canonical truth
- sponsor-facing pilot layers remain bounded and practical

When doing cleanup or alignment work:
- prefer clarification over redesign
- prefer cross-linking over duplication
- prefer additive correction over broad refactor
- preserve distinctions between canonical, semantic, governance, retrieval, and sponsor layers
- keep roadmap and phase logic dependency-aware

You may improve:
- README and reading order
- terminology consistency
- stale or duplicate docs
- cross-document references
- roadmap coherence
- doc structure and discoverability

You must not:
- rewrite the project into a generic ontology stack
- rewrite it as a generic RAG architecture
- remove or flatten the canonical spine concept
- discard the validation model
- replace the DNA address idea with a simpler convenience structure
- collapse governance and retrieval into one layer
- silently change design authority

Before proposing changes, explain:
1. what the repo is trying to do
2. what the core layers are
3. which files are design-authority docs
4. what is reusable vs Law Firm-specific
5. what should be left alone

When finished, produce:
- a concise alignment summary
- exact files changed
- why the changes improve coherence
- confirmation that the canonical spine and validation posture were preserved

---

Short version:
Preserve architecture first. Align second. Simplify only when it does not erase design intent.

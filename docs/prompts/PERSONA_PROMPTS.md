## CINO Prompt

You are reviewing a semantic-governance substrate and Innovation OS contract repository as a CINO-level strategic and operating artifact.

Explain this repository in business and architecture terms. Focus on:
- what problem it solves
- why the architecture is structured as a layered governed system
- how canonical meaning, runtime learning, document evidence, retrieval, and sponsor layers fit together
- how the mutation boundary protects canonical truth while still allowing operational learning
- what is useful now versus later
- what a reasonable next bounded investment would be

Do not treat this as an abstract ontology exercise. Treat it as a practical decision substrate and future AI-enablement foundation.

Your output should include:
1. executive summary
2. what is strategically strong
3. what is still missing
4. what could be reused elsewhere
5. the smallest smart next step

## Knowledge Management Director Prompt

Explain how this project works as a governed knowledge system. Focus on:

Pay special attention to:
- the system map and decision log
- the content stewardship model

Your output should include:
1. how KM should understand this system
2. what governance and stewardship model it implies

4. what KM could directly own

## Ontology or Knowledge Graph Engineer Prompt

You are reviewing this repository as an ontology or knowledge graph engineer.

Explain how the project is designed from one end to another. Focus on:
- design authority and semantic boundaries
- validation model and additive evolution
- the separation between taxonomy, ontology, runtime learning, and action surfaces
- provenance, document structure, and trust boundaries
- SHACL, JSON Schema, JSON-LD, and registry interactions
- why runtime learning objects and Innovation OS objects do not get to redefine canonical meaning

Do not rewrite the architecture into a different ontology pattern. First explain the design on its own terms. Then identify which parts are portable and which are repo-specific.

Your output should include:
1. architecture explanation
2. strongest design decisions
3. unusual but defensible design choices
4. what could be formalized further
5. what not to break if building on top of it

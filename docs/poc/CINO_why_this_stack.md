# Why This Stack

## Purpose

This note explains why the pilot uses a standards-aligned semantic stack while keeping substrate-native operating semantics as the core architecture.

## What The CINO Should Understand

This is not an abstract ontology exercise.
It is a governed decision substrate for a bounded pilot around intake, conflicts, and AI use.

## Why This Helps Now

The current problem is that policy logic often lives across documents, people, and workflow memory.

This pilot introduces a machine-readable layer that can make these questions clearer:
- what governs this answer
- what conflicts with it
- what source supports it
- what restriction changes the answer

## Why Reuse Standards

We reuse broad standards where they solve generic semantic problems well:
- provenance
- metadata
- concept labels
- graph packaging
- validation

That lowers risk and increases interoperability.

## Why Keep Substrate-Native Objects At The Center

The pilot still needs local meaning for things like:
- policy topic
- operating position
- governance baseline
- position assessment
- retrieval package
- proposal promotion

Those are the objects that make the pilot relevant to Law Firm operations.

## Why Some Standards Are Adopted Now, Some Selective, Some Later

Adopt now:
- low-regret foundation
- useful immediately
- directly supports the pilot

Selective:
- useful in bounded cases
- too heavy to impose everywhere yet

Watchlist later:
- promising for future legal-domain depth
- premature for the current pilot

## Why This Is A Good Proof Of Concept

It is small enough to govern, concrete enough for a bounded demonstration, and structured enough to scale into future KM and AI architecture work.

## What This Opens Next

If the pilot is approved to continue, the next build can add:
- query and answer payloads
- stewardship model for KM
- AI-facing retrieval contract
- exception handling and promotion workflow
- broader policy slices built on the same pattern

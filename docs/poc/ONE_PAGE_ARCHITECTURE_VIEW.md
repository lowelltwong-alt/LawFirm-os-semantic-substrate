# One-Page Architecture View

## Goal

Turn a bounded intake, conflicts, and AI-use workflow into a governed decision substrate that can later support knowledge management and Azure-based AI enablement.

## 1. Source Systems
- firm policy documents
- client outside counsel guidelines
- matter-specific restrictions
- explicitly quarantined AI-generated material

## 2. Governance Layer
- substrate-native operating semantics
- policy topics
- operating positions
- governance baselines
- exceptions and promotion paths
- provenance and review posture

## 3. Semantic Layer
- JSON-LD context
- named graph manifest
- projection contracts
- external standards registry
- bounded pilot mapping records

## 4. Validation Layer
- canonical validators
- strict external alignment validation
- repo-wide YAML parsing
- bounded semantic stack validation scaffold

## 5. Retrieval and Answer Layer
- asserted-first retrieval defaults
- access-aware filtering
- answer payload format
- next-action guidance
- escalation when review is required

## 6. Stewardship Layer
- author
- reviewer
- approver
- KM steward
- explicit lifecycle and promotion rules

## 7. Evaluation Layer
- supported questions
- gold questions
- policy correctness
- scope correctness
- provenance visibility
- governance integrity

## Why This Matters

This architecture keeps governance, provenance, and access control in place while preparing the organization for a future retrieval and AI layer that is bounded, explainable, and sponsor-ready.

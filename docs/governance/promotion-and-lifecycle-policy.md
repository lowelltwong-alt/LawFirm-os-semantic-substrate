# Promotion and Lifecycle Policy

Promotion changes governance posture and should never be treated as an implicit
side effect.

## Core Rules

- promotion actions should be explicit and logged
- lifecycle changes should reference governed action types
- boundary and quarantine material should not move into stronger partitions by default
- pilot slices should reach validation readiness before publication readiness

## Typical Flow

- `planned`
- `in_build`
- `validation_ready`
- `publication_ready`
- `archived`

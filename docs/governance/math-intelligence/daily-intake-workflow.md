# Daily Intake Workflow

Use this checklist for routine math-intelligence intake.

## Intake steps

1. Capture the candidate signal.
2. Assign source type and source status.
3. Assign proof status.
4. Assign one or more math-domain tags.
5. Assign one or more project-surface impact tags.
6. Assess whether the item is architecturally relevant.
7. Choose one recommendation:
   - `ignore`
   - `watch`
   - `summarize`
   - `deep_research`
   - `prototype`
   - `update_roadmap`
   - `create_adaptation_proposal`
8. Decide whether to create:
   - a watch item
   - a summary
   - a roadmap note
   - a deep-research prompt
   - a prototype recommendation
   - an adaptation-proposal recommendation
9. Record evidence limits and uncertainty.
10. Stop unless a reviewed follow-up is explicitly approved.

## Deep-research rule

`deep_research` means a scoped follow-up research task or prompt. It is not verified truth, not automatic canon change, and not automatic runtime implementation.

## Governed path

Use this route as a governed-learning input surface for governed recursive improvement:

`candidate signal -> assessment -> recommendation -> adaptation-proposal recommendation if reviewed -> promotion-decision only through existing authority path`

## Explicit non-goals

- autonomous action loop
- source-ingestion feed
- runtime implementation
- repo rewriting
- direct promotion decision creation

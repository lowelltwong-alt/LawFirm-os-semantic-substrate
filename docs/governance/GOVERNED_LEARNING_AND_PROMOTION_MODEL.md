# Governed Learning and Promotion Model

## Purpose

Define how the repository should convert weak signals into stronger knowledge without allowing unsafe or silent self-modification.

## Core Principle

The system should be able to learn, but learning must remain governed.

That means:
- not every signal becomes a baseline change
- not every inference becomes promoted truth
- not every useful retrieval tweak should rewrite semantic meaning

## The Promotion Ladder

The repository should treat these as distinct stages:

### 1. Feedback
A signal that a user, steward, validator, or retrieval path encountered a gap, ambiguity, inconsistency, or friction point.

### 2. Inference
A derived interpretation or hypothesis that may help explain or route the issue, but has not yet earned stronger authority.

### 3. Proposal
A structured candidate change made explicit for review.

### 4. Reviewed Improvement
A proposal that has been checked against provenance, trust boundaries, validation posture, and operating intent.

### 5. Promoted Baseline
A reviewed change that is accepted into the stronger operating layer.

## Why This Separation Matters

This separation prevents four failure modes:
- feedback being mistaken for truth
- inference being mistaken for policy
- convenience-driven retrieval changes silently changing meaning
- experimental material contaminating the stronger baseline

## Promotion Checks

Before a learning signal should be promoted, it should be checked for:
- provenance clarity
- source support
- trust boundary impact
- validation compatibility
- operating usefulness
- stewardship ownership
- drift risk

## Non-Negotiable Rules

- no silent promotion into stronger baselines
- no collapse of quarantine, inferred, and asserted material into one layer
- no change should bypass the canonical spine and validation path
- promotion decisions should remain explainable and reviewable
- feedback capture should be easier than baseline modification

## Stewardship Role

The learning loop should remain steward-guided even when AI is used to surface patterns, summarize gaps, or propose improvements.

The KM lead, reviewer, or designated architecture steward should remain part of the stronger promotion path.

## Validation Role

Validation should act as a control point in the learning loop.

A change is not stronger merely because it is useful.
A change is stronger when it is both useful and aligned to the canonical spine, the validation path, and the governance model.

## Safe Growth Pattern

Recommended pattern:
1. capture signal
2. classify it
3. route it to a governed proposal path
4. review it
5. validate it
6. promote it if approved
7. measure whether the promotion improved the system

## Summary

The repository is intended to become a living system through governed promotion, not through uncontrolled recursion.

# Capability Taxonomy

This taxonomy defines the top-level functional families for capability cards.

## Top-level families

- `reasoning_planning`
- `retrieval_grounding_access`
- `validation_assurance`
- `transformation_generation`
- `workflow_orchestration`
- `monitoring_detection`
- `audit_governance_compliance`
- `registry_taxonomy_knowledge_graph`
- `learning_promotion_adaptation`
- `adapter_interface`
- `synthetic_test_simulation`

## Taxonomy intent

This taxonomy is substrate-neutral. It is meant to organize capability surfaces across different tool ecosystems without letting any single vendor naming convention define semantic authority.

## Mapping rule

Every canonical card should map to one or more taxonomy families through `capability_taxonomy_tags`. The taxonomy should remain stable enough to support future derived indexes and cross-platform summaries while remaining governed and reviewable.

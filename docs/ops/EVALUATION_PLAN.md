# Evaluation Plan

## Purpose

Define how the pilot will be evaluated for usefulness, correctness, and governance integrity.

## Evaluation Goals

- determine whether answers are operationally useful
- verify that answers remain governance-correct
- ensure that provenance and source support remain visible
- detect drift before broader rollout

## Core Evaluation Dimensions

### 1. Policy Correctness
Does the answer align with the governing baseline, restriction, or exception path?

### 2. Scope Correctness
Does the answer respect the matter, client, or workflow boundary?

### 3. Source Support
Are the governing basis and supporting artifacts visible and traceable?

### 4. Actionability
Does the answer provide a clear next action for the user?

### 5. Governance Integrity
Did the answer avoid surfacing restricted or quarantine-only material inappropriately?

## Evaluation Inputs

- supported questions set
- gold questions
- expected answer structure
- reviewer feedback
- provenance and promotion records

## Minimum Review Pattern

Each gold question should be reviewed for:
- answer behavior
- status correctness
- scope correctness
- supporting basis clarity
- next-action usefulness

## Success Signals

- consistent answers across repeated review
- clear supporting basis
- limited ambiguity in status assignment
- no inappropriate surfacing of restricted content

## Failure Signals

- unsupported answers
- governance drift
- missing provenance
- incorrect scope handling
- unclear next actions

## Why This Matters

A proof of concept is only credible if it can show not just interesting answers, but governed and repeatable review behavior over a bounded evaluation set.

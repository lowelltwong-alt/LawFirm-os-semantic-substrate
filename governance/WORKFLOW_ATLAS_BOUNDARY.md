# Workflow Atlas Boundary

Workflow Atlas is a candidate discovery and meeting-prep layer.

It may extract workflow atoms, create diagrams, create correction events, create ontology delta candidates, create integrity reports, create priority colorings, and emit Exception Lake evidence candidates.

It must not create canonical route IDs, create canonical event classes, mutate schemas, update ontology truth, approve a digital-twin update, or store raw privileged transcripts in the Exception Lake.

## Truth ladder

1. Spoken: a person said it.
2. Diagrammed: AI mapped it.
3. Corrected: a human corrected it.
4. Corroborated: independent evidence supports it.
5. Observed: system or task mining confirms it.
6. Approved: governance promotes it.

Only approved objects become canonical substrate or digital-twin truth.

## Same-job integrity

At scale, at least two people with the same job role should complete the same short intake before the workflow is treated as stable.

Disagreements should create integrity findings, not accusations.

## Microsoft house fit

Microsoft implementation surfaces such as Teams, Graph, Entra, Purview, SharePoint, Planner, Power Automate, Fabric, and Copilot Studio may provide evidence and review surfaces.

They are implementation sources, not semantic authority.

# AIRCA Alignment

Author: Lowell T. Wong

This document explains how the ontology repository aligns with the AIRCA + Fractal Decision Architecture repository.

## Core Position

This ontology system is AIRCA-aligned infrastructure.

It is not AIRCA itself. Rather, it is a fractal ontology and machine-readable artifact layer that fits primarily within the **Architect** layer of AIRCA while enabling higher-quality **Inform** functions.

## Why this fits AIRCA

The AIRCA repository defines AIRCA as an AI-era adaptation of RACI and explicitly includes:
- fractal ontology as recursive relationship logic
- machine-readable artifact design as an operational layer
- classification, meaning, accountability, review, lifecycle logic, durable decision memory

This ontology repo directly supports those aims by defining:
- stable entities
- typed relationships
- claim structures
- authority boundaries
- validation rules
- provenance and evidence logic

## Layer Mapping

### Architect
Primary fit.

The ontology belongs here because it defines:
- what entities exist
- what relationships are allowed
- what authority contexts govern interpretation
- what validation and governance rules apply

### Inform
Secondary fit.

The ontology enables Inform by improving:
- retrieval
- evidence surfacing
- multi-hop traversal
- AI-readable context packaging

### Rank
Future-adjacent.

Some future ontology features may support Rank, such as:
- confidence models
- source weighting
- promotion logic
- conflict prioritization

### Commit
Supportive, but not primary.

The ontology can support Commit by making evidence, authority, and provenance visible to decision-makers.

### Act
Future-adjacent.

Automated validation pipelines, release gates, and promotion workflows would extend ontology operations into Act.

## Defensible Framing

The cleanest position is:

> This ontology and concordance system is an AIRCA-aligned fractal ontology and machine-readable artifact layer. It belongs primarily in Architect because it structures entities, relationships, governance, and interpretation boundaries. It also enables Inform by making knowledge retrievable, evidence-addressable, and traversable for AI systems.

## Practical Repo Mapping

- `DEFENSE_APPENDIX.md` -> Architect
- `CLAIM_SCHEMA.md` -> Architect
- `AUTHORITY_MODEL.md` -> Architect
- future retrieval bundles -> Inform
- future ranking or promotion logic -> Rank
- future CI enforcement and workflow automation -> Act
